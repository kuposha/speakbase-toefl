# Speakbase — спецификация грамматической программы для реализации

**Версия:** 1.0
**Статус:** рабочая спецификация; до изменения пользовательских данных обязательны review эталонного урока, миграционный план и тесты.
**Связанные документы:** `GRAMMAR-CURRICULUM-A1-C1.md`, `GRAMMAR-SOURCE-MAP.md`, `GRAMMAR-MIGRATION-MAP.md`.

## 1. Неизменяемая идентичность курса

- Идентификатор блока — его постоянный `curriculumId`, например `A1-05`. Он не зависит от позиции в массиве, номера урока в интерфейсе, названия или порядка сортировки.
- Все 94 ID из curriculum v1 считаются зарезервированными и неизменяемыми. Нельзя переиспользовать ID для другой темы.
- Переименование темы не меняет ID. Существенное изменение цели/содержания создаёт новую версию блока или новый ID с явной записью supersedes.
- `curriculumVersion` и `lessonContentVersion` хранятся отдельно: изменение объяснения или упражнений не должно менять идентичность темы.
- Удалённый/заменённый блок не удаляется физически из истории. Он получает статус deprecated и ссылку на замену.
- UI-порядок хранится отдельно от ID. Нельзя использовать индекс массива как ключ прогресса, расписания, аналитики или истории.

## 2. Обязательные поля блока

Каждый блок обязан иметь следующие поля до включения в учебный маршрут:

| Поле | Назначение |
|---|---|
| `curriculumId` | Постоянный ID, уникальный в пределах курса |
| `curriculumVersion` | Версия карты тем |
| `title` | Название темы |
| `cefrLevel` | Явное значение A1/A2/B1/B2/C1; никогда не вычисляется из индекса |
| `sequence` | Порядковый номер для отображения, не идентичность |
| `prerequisites` | Массив ID обязательных предварительных блоков |
| `learningOutcomes` | Наблюдаемые действия ученика, не расплывчатое «понимать тему» |
| `scope.included` | Что именно обучается в этом блоке |
| `scope.excluded` | Что намеренно оставлено для последующих блоков |
| `sourceRefs` | Источник, издание, unit, PDF-страницы и статус проверки |
| `toeflLinks` | Типы заданий TOEFL, где навык применяется; пустой массив допустим |
| `status` | planned / drafted / source-verified / editorial-reviewed / learner-tested / published |
| `contentVersion` | Версия конкретного текста урока и банка заданий |

Текущая таблица curriculum уже содержит названия, CEFR-группы, первичные outcomes и тематические ссылки на источники. Эта спецификация дополняет её постоянными зависимостями и требованиями к реализации; недостающие поля должны быть внесены в структурированный каталог до миграции.

## 4. Контракт содержания урока

Урок — не одна HTML-лекция и не набор вопросов. Полноценный блок должен состоять из следующих частей.

### Обязательный порядок для ученика

**Сначала ученик получает весь теоретический материал целиком, затем переходит к диагностике и практике.** Нельзя дробить обязательную теорию на небольшие порции, которые открываются только после ответов на упражнения. Диагностика может быть показана до теории только как явно необязательный режим проверки себя; основной учебный маршрут всегда начинается с полного конспекта.

Теория должна быть удобна для ведения бумажного/цифрового конспекта: определения, назначение, формулы, образование форм, условия выбора, исключения, ограничения, контрасты, произношение (когда применимо), примеры с переводом и типичные ошибки. Необходимые для заявленных целей правила нельзя скрывать за кнопками «подробнее» или оставлять на потом. Краткая шпаргалка может быть дополнением, но не заменяет полный конспект.

После теории ученик переходит к диагностике/prerequisite check, управляемой практике, самостоятельной практике и production. Страница/раздел теории остаётся доступным для повторного открытия после завершения урока и во время практики. Ученик может проходить практику в своём темпе; фиксированное ограничение по минутам не применяется. Ориентировочная длительность — справочная оценка, а не условие завершения.

1. **Learning goals:** 2–5 измеримых целей в формулировках «ученик может…».
2. **Concept map:** кратко — смысл, форма, выбор формы и границы применения.
3. **Core explanation:** полный русскоязычный конспект без ложных абсолютов; английские примеры с точным переводом.
4. **Entry check:** 3–6 коротких заданий на prerequisites; в основном маршруте показывается после полного конспекта. Результат не считается освоением новой темы.
5. **Form builder:** affirmative / negative / question / short answer — только те формы, которые входят в scope этого блока.
6. **Meaning and contrast:** минимум два контекста, где выбор формы меняет смысл; контраст с близкой конструкцией, если это часть цели.
7. **Usage boundaries:** исключения, ограничения, регистр, вариативность и случаи, которые нельзя обобщать.
8. **Typical L1 errors:** ошибки русскоязычных учеников с объяснением причины, а не только исправленной строкой.
9. **Guided practice:** пошаговая практика с уменьшающейся поддержкой.
10. **Independent practice:** задания без подсказки, включая перенос на незнакомый контекст.
11. **Production task:** короткий собственный ответ; для подходящих тем — применение в TOEFL Writing/Speaking.
12. **Answer key:** правильный ответ, причина, почему он подходит, и объяснение каждого правдоподобного distractor.
13. **Exit check:** новые задания на ту же цель, не повторяющие формулировки из объяснения.
14. **Spaced review:** повторение по фактическим ошибкам и уверенности, а не просто повторение всей темы по фиксированному календарю.

## 5. Требования к упражнениям и ключам

- У каждого задания есть `itemId`, `curriculumId`, `skillTarget`, `interactionType`, `prompt`, `answerKey`, `rationale`, `distractorRationales`, `difficulty`, `sourceBasis` и `contentVersion`.
- Закрытый вопрос имеет один однозначный ключ либо явно заданный список допустимых вариантов. Если вариантов несколько, это отражено в схеме проверки.
- Открытый ответ не получает бинарное «верно/неверно» по одному совпадению со строкой модели. Оцениваются целевая конструкция, грамматическая корректность, смысл и полнота; допустимые варианты перечисляются.
- Дистрактор проверяет конкретное заблуждение. Запрещены случайные грамматически невозможные варианты, которые не помогают диагностике.
- Сложность повышается поэтапно: распознавание → контролируемое построение → выбор в контексте → редактирование ошибки → самостоятельное применение.
- Повторение должно менять контекст и формулировку. Нельзя создавать видимость освоения за счёт заучивания одного предложения.
- Ключи и объяснения проверяются отдельным тестом: правильный ответ действительно допустим, неверные варианты объяснимы, формулировка не двусмысленна.

## 6. Источниковая дисциплина

Статусы источника для каждого утверждения:
- `toc-mapped` — тема найдена в оглавлении/unit, но содержание страницы не проверено;
- `page-verified` — целевые страницы открыты и конкретное правило/ограничение проверено;
- `cross-checked` — подтверждено независимым надёжным источником или второй грамматической опорой;
- `needs-source` — текущих материалов недостаточно, урок не публикуется до дополнительной проверки.

В метаданных хранить название и издание книги, unit, номер страницы PDF, печатную страницу (если читаема), проверяемое утверждение и дату редакторской проверки. Нельзя выдавать номер unit за страницу.

Примеры Speakbase создаёт самостоятельно. Учебник используется как проверяемая опора, а не как источник для копирования готовых упражнений. EGP/Cambridge English Profile — свидетельство уровневого употребления, не единственный источник правил. Для GR-03 обязательно визуально проверять скан. Для nominalisation/stance и пунктуации не публиковать теорию, пока не закрыт статус `needs-source`.

## 7. Связь с TOEFL 2026

У каждого блока можно указать несколько применений, но не нужно искусственно привязывать каждую тему ко всем заданиям:
- Reading: структура предложения, modifiers, reference, connectors, clause relations.
- Listening: tense/aspect, modality, reduced forms, stance, discourse relations.
- Writing — Build a Sentence: word order, clause patterns, complementation, agreement.
- Writing — Email: ясность, просьбы, вежливость, время, связность и регистр.
- Writing — Academic Discussion: аргументация, concession, comparison, hedging, reporting.
- Speaking — Listen and Repeat: точность воспроизведения групп слов, окончаний и auxiliary verbs.
- Speaking — Take an Interview: контроль времени, разнообразие clauses, точность и развитие ответа.

TOEFL-применение — контекст переноса, а не замена общей коммуникативной цели темы. Формат экзамена и критерии заданий ведутся отдельно по актуальным материалам ETS.

## 8. Состояния освоения и аналитика

Статус освоения не равен факту открытия страницы. Минимальные состояния:
- `not_started`
- `diagnostic_seen`
- `learning`
- `practising`
- `needs_review`
- `provisionally_mastered`
- `mastered`

Переход к mastered требует нескольких независимых свидетельств: exit check, отсроченное повторение и перенос в новый контекст. Для устного/письменного задания сохраняются rubric scores и версия rubric. Неизвестный результат не превращается в ноль или в mastered.

## 9. Критерии готовности к публикации

Блок нельзя считать published, пока:
- ID, CEFR, sequence, prerequisites и scope проверены автоматическими тестами;
- все заявленные outcomes действительно проверяются заданиями;
- правила и примеры source-verified;
- каждый ключ и distractor прошёл отдельную проверку;
- русский текст понятен начинающему без внешнего объяснения;
- нет противоречий между лекцией, практикой и обратной связью;
- lesson flow проверен на телефоне и компьютере;
- прогресс сохраняется по curriculumId и не меняет смысл старых данных;
- блок прошёл редакторскую проверку и тестирование реальным учеником.

**Важно:** этот документ фиксирует контракт будущей реализации. Он не означает, что 94 урока уже написаны или проверены, и не разрешает автоматически мигрировать старые completion marks.
